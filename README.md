# Организаторы МП — Discord-бот для отдела организаторов Arizona RP

Бот ведёт **полный жизненный цикл мероприятий (МП)**: от идеи и заявки до проверки отчёта и архива, с кадровыми решениями, тестированием, стажировками, системой достижений, журналом аудита и автоматическим планировщиком.

Все данные хранятся в базе данных (SQLite по умолчанию) — бот переживает рестарты без потери состояния. Демо- и заглушек-данных в системе нет: каждая команда, кнопка и форма работают с реальными записями.

## Возможности

- **Жизненный цикл МП**: заявка → согласование → планирование → проведение → отчёт → архив.
- **29 slash-команд** с автодополнением кодов мероприятий, сотрудников и материалов.
- **Кнопки и формы прямо в Discord**: подача заявки, одобрение/доработка/отклонение, редактирование, отчёт, архив, история статусов.
- **Мост анонсов МП**: при планировании/запуске/завершении/отмене бот публикует анонс в тестовый канал `📣・анонсы-мп` сервера организаторов (или в webhook официального сервера, `ANNOUNCE_WEBHOOK_URL`). В приглашении кнопка **«✅ Записаться»** — записи хранятся в БД, у организатора список участников до старта; после завершения в анонсе появляются **кнопки оценки 1–5**.
- **Двойные брони**: создание/редактирование даты проверяется на пересечение с уже запланированными МП — конфликт перечисляется с кодом, временем и организатором.
- **Чек-лист подготовки МП**: каналы/голосовая/анонс закрываются ботом автоматически, ручные пункты (команда, материалы, роли) — кнопками; незакрытые пункты **блокируют запуск**.
- **Учёт посещаемости по голосу**: бот слушает голосовые каналы, фиксирует сессии и минуты; сводка публикуется при завершении, сверяется с отчётом (защита от накрутки участников).
- **Оценки МП**: участники ставят 1–5 звёзд в анонсе завершения; средняя оценка и распределение — по кнопке «Оценки».
- **Ротация организаторов** (`/rotation`): кто давно не проводил МП и кто свободен в указанное время.
- **База материалов для игр** (`/material`): вопросы, темы, сценарии — поиск по названию/тегам/тексту, привязка к МП.
- **Центр матрица прав** (`PermissionService`): проверка прав выполняется на backend для каждой команды, кнопки, модалки и селекта. Скрытие команд в Discord — лишь UX.
- **Журнал аудита**: каждое значимое действие (согласование, назначение, кадровое решение, настройка) пишется в `AuditLog` и дублируется в канал логов.
- **Планировщик**: автозапуск МП по времени, напоминания о приближающемся МП, напоминания о просроченных отчётах, автоархив, очистка голосовых каналов, истечение попыток тестов, перестройка панелей.
- **Восстановление после рестарта**: состояние хранится в БД; при старте бот пересоздаёт недостающие каналы, обновляет панели и выполняет первый тик планировщика (пропущенные события догоняют расписание).
- **Информационные панели** (борды): планирование, активные МП, статистика — обновляются из БД автоматически и по кнопке «Обновить».
- **Тестирование**: тесты с вопросами, попытками, проходным баллом и ролью за успешную сдачу; прохождение в ЛС с восстановлением после рестарта.
- **Кадровая система**: должности, повышение/понижение с указанием причины, предупреждения и выговоры со сроком действия, стажировки.
- **Достижения**: критерии хранятся в БД, вычисляются из реальной статистики.
- **Статистика**: периоды (сегодня/неделя/месяц/год/всё время), разбивка по категориям и организаторам.
- **Два сервера**: `GUILD_ID` — сервер отдела организаторов, `OFFICIAL_GUILD_ID` — официальный сервер, где проходят МП; бот приглашается в оба, каналы мероприятий (текстовый и голосовой) создаются на официальном, если он задан.

## Жизненный цикл мероприятия

```
ИДЕЯ/ЧЕРНОВИК → ЗАЯВКА → НА ПРОВЕРКЕ → ▶ ОДОБРЕНО → ЗАПЛАНИРОВАНО → ▶ ИДЁТ
                     ↑        │                                      │
                  ДОРАБОТКА ───┘                                      ▼
                     │        ▼                                 ЗАВЕРШЕНО → ОТЧЁТ СДАН → АРХИВ
                     └── ОТКЛОНЕНО                                (отчёт)      (проверен)
        Любой согласованный статус может быть ОТМЕНЁН с указанием причины.
```

- Допустимые переходы описаны таблицей `TRANSITIONS` (`src/services/rules.ts`) — произвольная смена статуса невозможна.
- Каждый переход атомарен (условие в БД + запись истории + аудит) — двойной клик по кнопке не задвоит действие.
- Повторная подача после доработки создаёт новую запись `Application` с увеличенным номером попытки.

## Мост анонсов, чек-лист и участие

- **Анонс-мост** (`src/services/announcements.ts`): при переводе в `ЗАПЛАНИРОВАНО` бот публикует приглашение, при запуске — «МП началось», при завершении — «МП завершено» с кнопками оценки, при отмене — уведомление. Одно сообщение на МП обновляется по мере смены статусов. Цель: `ANNOUNCE_WEBHOOK_URL` (официальный сервер) → `announceWebhookUrl` из БД → канал `📣・анонсы-мп` (тест на сервере организаторов).
- **Записи «✅ Записаться»**: кнопка в приглашении, переключается повторным нажатием, счётчик обновляется в анонсе. Список — кнопка `Участники` в карточке МП.
- **Чек-лист** (`src/services/checklist.ts`): создаётся при одобрении. `Каналы МП созданы` и `Голосовой канал готов` закрываются ботом автоматически; `Анонс опубликован` — при успешной публикации (или кнопкой «Объявление»); `Команда`, `Материалы`, `Роли` — вручную. Запуск МП блокируется, пока есть незакрытые пункты (кроме автозапуска по расписанию).
- **Посещаемость** (`src/services/attendance.ts`): `voiceStateUpdate` фиксирует сессии в голосовом канале МП. При завершении сводка публикуется в канале МП; отчёт сверяется с фактом (расхождение >30% — предупреждение).
- **Двойные брони** (`src/services/schedule.ts` + `rules.ts`): создание заявки и смена даты проверяются на пересечение с `APPROVED/PLANNED/ACTIVE` мероприятиями.

## Права доступа

Реальная проверка прав — на backend (`src/permissions/matrix.ts`), для **каждого** действия:

| Должность | Права |
|---|---|
| Главная Администрация | все права, включая `/setup` |
| Куратор | согласование, назначение, архив, кадры, дисциплина, тесты, стажировки, логи |
| Главный Организатор МП | как Куратор, без `/setup` |
| Старший Организатор МП | согласование, назначение, архив, редактирование чужих МП, дисциплина, тесты, стажировки |
| Организатор МП | подача заявок, свои МП, статистика |
| Помощник Организаторов | подача заявок, участие, статистика |
| Не состоит в отделе | только публичные разделы |

Роли Discord (`VIS_*`-биты на командах) — видимость в меню, не защита. Требуемая роль бота: **роль бота выше создаваемых ролей**.

## Установка и запуск

Требования: **Node.js ≥ 20**, npm, аккаунт Discord с созданным приложением.

```bash
# 1. Зависимости
npm install

# 2. Переменные окружения
copy .env.example .env      # Windows: cp .env.example .env — на Linux/macOS
# заполните DISCORD_TOKEN и GUILD_ID в .env

# 3. База данных
npm run db:push             # создать/обновить схему

# 4. Справочники (достижения, категории МП, настройки) — идемпотентно
npm run seed

# 5. Проверка
npm run check               # typecheck + unit-тесты

# 6. Запуск
npm run dev                 # разработка (tsx watch)
npm run build && npm start  # продакшн (компиляция в dist/)
```

После запуска выполните `/setup` в Discord на сервере из `GUILD_ID` — бот создаст роли, каналы, панели и справочники (при повторном запуске просто синхронизирует существующее).

**Приглашение бота**: Developer Portal → OAuth2 → URL Generator → `bot` + `applications.commands`, нужные права: управление ролями, каналами, отправка сообщений, управление эмодзи (полный список — в `constants.ts`).

## Переменные окружения

Файл `.env` (никогда не попадает в Git — см. `.gitignore`), пример — `.env.example`:

| Переменная | Обязательна | Описание |
|---|---|---|
| `DISCORD_TOKEN` | да | токен бота |
| `GUILD_ID` | рекомендуется | ID сервера организаторов для точечной регистрации команд и настройки; без неё команды регистрируются глобально |
| `OFFICIAL_GUILD_ID` | нет | ID официального сервера (где проходят МП): команды регистрируются и там, каналы мероприятий создаются на нём |
| `ANNOUNCE_WEBHOOK_URL` | нет | webhook для анонсов МП на официальном сервере; без него анонсы идут в `📣・анонсы-мп` сервера организаторов |
| `DATABASE_URL` | да | строка подключения Prisma (`file:./prisma/data.db` для SQLite) |
| `LOG_LEVEL` | нет | `debug` \| `info` \| `warn` \| `error` (по умолчанию `info`) |
| `SCHEDULER_TICK_MS` | нет | период тика планировщика, мс (по умолчанию 60000) |
| `REMINDER_MINUTES_AHEAD` | нет | напоминание за N минут до МП (60) |
| `REPORT_REMINDER_MAX` | нет | максимум напоминаний об отчёте (3) |
| `AUTO_ARCHIVE_DAYS` | нет | автоархив через N дней после отчёта (7) |
| `VOICE_CLEANUP_DELAY_MINUTES` | нет | удаление voice-канала через N минут после завершения (30) |
| `BOARDS_EVERY_TICKS` | нет | перестройка панелей каждый N-й тик (15) |

Помимо `.env`, часть настроек хранится **в БД** (`GuildSettings`): проходной балл теста, лимит попыток, срок сдачи отчёта, задержка удаления voice-канала — это реальные настройки, применяемые ботом. К ним же относится цель анонсов: канал `announceChannelId` (заполняется `/setup`) и `announceWebhookUrl` (приоритет над `ANNOUNCE_WEBHOOK_URL`).

## База данных: SQLite и переход на PostgreSQL

По умолчанию используется **SQLite** — нулевая настройка, данные в `prisma/prisma/data.db` (путь получается из `DATABASE_URL="file:./prisma/data.db"` относительно файла схемы). Для одной копии бота этого достаточно.

Переход на PostgreSQL:

1. В `prisma/schema.prisma` замените `provider = "sqlite"` на `provider = "postgresql"`.
2. Задайте `DATABASE_URL="postgresql://user:password@host:5432/db?schema=public"` в `.env`.
3. Выполните `npx prisma db push` (или `npx prisma migrate dev --name init` для истории миграций).
4. Перенесите данные при необходимости (SQLite → PostgreSQL через `prisma db pull`/экспорт) и запустите `npm run seed`.

Схема сознательно не использует enum/JSON-типы SQLite: статусы — строки, варианты ответов — JSON-строки, поэтому перенос на PostgreSQL тривиален.

## Планировщик и восстановление после рестарта

`src/scheduler/index.ts` — тик раз в `SCHEDULER_TICK_MS` (защита от параллельного выполнения):

1. `autoStartDueEvents` — автозапуск МП, у которых наступило время.
2. `notifyUpcomingEvents` — напоминание за `REMINDER_MINUTES_AHEAD` минут (флаг `upcomingNotifiedAt` в БД, повторно не шлётся).
3. `remindOverdueReports` — напоминания о просроченных отчётах (счётчик `reportReminderCount` ≤ `REPORT_REMINDER_MAX`).
4. `autoArchiveReported` — архивация `REPORTED` старше `AUTO_ARCHIVE_DAYS`.
5. `cleanupExpiredVoiceChannels` — удаление voice-каналов завершённых МП.
6. `expireStaleAttempts` — истечение застарелых попыток тестов.
7. Каждый `BOARDS_EVERY_TICKS`-й тик — перестройка панелей.

`src/scheduler/recovery.ts` при старте: восстановление каналов текущих МП (`restoreEventChannels`, идемпотентно), обновление всех панелей, первый тик — пропущенное за время рестарта догоняется расписанием.

Все ключи состояния — в БД, а не в оперативной памяти.

## Рекомендации по развёртыванию

- **Одна копия бота** на сервер: экземпляры работают с одной БД и могут задвоить уведомления.
- Используйте менеджер процессов (`pm2`, `nssm`, Windows Service) с автоперезапуском.
- Бэкап `prisma/prisma/data.db` (или регулярные дампы PostgreSQL).
- Секреты только в `.env` — файл исключён из Git; `.env.example` содержит лишь структуру.
- `npm run build && npm start` вместо `dev` на сервере.
- Обновления: `git pull` (если репозиторий подключён) → `npm install` → `npm run check` → `npm run db:push` → перезапуск.

## Устранение неполадок

| Симптом | Решение |
|---|---|
| `Отсутствует обязательная переменная окружения DISCORD_TOKEN` | заполните `.env` (см. `.env.example`) |
| Бот не отвечает на команды | проверьте токен, приглашение с `applications.commands`, перезапустите |
| «База данных недоступна» | `npm run db:push`, проверьте `DATABASE_URL` |
| Команды не появились на сервере | проверьте `GUILD_ID` (ID сервера, не название); команды регистрируются глобально с задержкой до 1 часа |
| `EPERM ... query_engine-windows.dll.node` при `prisma generate` | DLL удерживает запущенный бот — остановите процесс и повторите |
| Панель не обновляется | кнопка «Обновить» на панели или дождитесь тика планировщика |
| Права «не работают» для роли Discord | проверьте иерархию ролей: роль бота должна быть выше создаваемых ролей; сами права проверяются ботом по БД |

Журнал бота: консоль (`LOG_LEVEL=debug` — подробный).
